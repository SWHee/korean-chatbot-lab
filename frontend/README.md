# frontend

핀봄의 현재 대표 Next.js 상담 화면입니다. 같은 FastAPI Agent API 위에서 법령 근거와
금융상품 정보를 읽기 쉬운 상담 경험으로 안내합니다.

## 실행

FastAPI(`uv run fastapi dev`)가 `127.0.0.1:8000`에 떠 있는 상태에서:

```bash
cd frontend
npm install
npm run dev
```

`http://localhost:3001`에서 확인합니다. 기존 개발 확인 주소와의 호환성을 위해 포트는
3001을 유지합니다. backend 주소는
`CHATBOT_API_URL` 환경변수로 바꿀 수 있습니다.

## 설계 방향 — 현대적인 금융 상담 서비스

`ref/`의 참조 이미지 두 장(한국 금융 챗봇 시안)과 Codex 검토를 바탕으로, 이전
아이보리·딥그린 종이 톤에서 **회청·네이비 계열**로 옮겼습니다.
스킬 조회에서는 스타일 계열로 **Soft UI Evolution**(부드러운 그림자, 은은한 깊이,
WCAG AA+)이 나와 그 방향을 따랐습니다.

| | 값 |
| --- | --- |
| 배경 | `#F5F7FA` |
| 카드 | `#FFFFFF` |
| 본문 | `#172033` |
| 주색 (서비스 동작) | `#244A6B` |
| 보조색 (법령 근거) | `#2F6B64` |
| 경계선 | `#DCE2E8` |
| 모서리 | 6 / 10 / 14px |
| 서체 | Pretendard (전면 산세리프) |

명조와 모노스페이스는 전부 걷어냈습니다. 조문 번호를 큰 명조로 쓰던 방식은
법률 문서의 권위보다 "에디토리얼 포트폴리오" 인상을 먼저 줬습니다.

### 대화 정렬 — 비대칭

말풍선을 양쪽에 두는 메신저 형태 대신, 참여자별로 다른 형태를 씁니다.

```
                                    [ 사용자 질문 ]   ← 오른쪽, 최대 68%
  ◍ 핀봄                                              ← 아바타+이름 1회
  답변 본문을 폭 전체로 넓게 표시                        ← 왼쪽, 말풍선 없음
```

긴 답변을 말풍선에 가두지 않으면서도 참여자 구분은 분명해집니다. 아바타와
이름은 답변 시작점에만 한 번 나오고, 스트리밍 중에 반복되지 않습니다.

사용자 아바타는 두지 않았습니다. 카드가 이미 오른쪽 정렬로 화자를 구분하고
있어 아바타를 더하면 같은 정보를 두 번 말하게 됩니다.

### 근거 카드

```
근거 1  예금자보호법
제35조의3
시행 2026.01.02
```

조문 번호 17px/600, 법령명 14px, 시행일과 근거 번호 12px의 산세리프입니다.

Codex가 제안한 네 번째 줄 — "보험금 지급 한도를 판단하는 근거입니다" 같은
사용 이유 — 은 **넣지 않았습니다.** backend의 `AgentSource`는
`source_id`·`law_name`·`article_no`·`effective_date`만 내려 주고 조문이 왜
선택됐는지는 주지 않습니다. 지어내면 근거 화면이 근거 없는 문장을 갖게 되므로,
필요하다면 tool 응답에 필드를 추가하는 쪽이 맞습니다.

### 색 규칙

신호색은 둘입니다. **네이비는 서비스 동작**(버튼, 링크, 포커스, 아바타),
**청록은 법령 근거**(각주 칩, 근거 라벨, 최고금리)에만 씁니다.

### 화면에 두지 않는 것

`/ask-agent/stream`이 내려 주는 진행 단계, 도구 호출 내역, `route`, 실행 시간은
표시하지 않습니다. 실제 사용자는 답이 어떤 경로로 만들어졌는지에 관심이 없고,
실행 시간(15초대)은 크게 쓸수록 "느리다"는 인상만 남습니다. 대신 기다리는 동안
단계 이름을 문장으로 바꿔 보여 줍니다 — `tools` → "법령과 상품 정보를 찾고 있어요".

반대로 근거 조문은 접지 않습니다. 과정이 아니라 신뢰의 근거라서 오히려 크게 씁니다.

## 기존 UI와의 차이

| | 이전 디자인 방향 | 현재 `frontend/` |
| --- | --- | --- |
| 톤 | 아이보리 종이 · 딥그린 · 하드 오프셋 그림자 | 회청 배경 · 네이비 · 부드러운 그림자 |
| 서체 | Georgia 세리프 헤드라인 | 전면 Pretendard 산세리프 |
| 모서리 | 각짐 (0) | 6~14px |
| 레이아웃 | 마케팅 히어로 + 채팅 카드 | 대화 카드 (+ 근거가 생기면 옆에 근거 카드) |
| 대화 표현 | 양쪽 말풍선 + 아바타 | 질문은 오른쪽 카드, 답변은 왼쪽 문서형 |
| 답변 조판 | 평문 (Markdown 기호 노출) | 제목·목록·강조 위계로 조판 |
| 근거 표시 | 없음 | 조문 카드 · 금리 비교 |

## 확인한 범위

- `npm run build`(타입 검사 포함) 통과
- FastAPI를 띄운 상태에서 `POST /api/chat` 프록시로 실제 Agent 스트림 1건 수신.
  status 4건 · token 26건 · result 1건이 도착했고, `route`는 `ready`,
  `sources` 5건, `tools` 1건(`search_law_articles`, status `ok`)이었습니다.
- 그 실제 답변 문자열로 `parseBlocks`를 돌려 15개 블록(제목 5·목록 4·문단 6)과
  강조 8개로 분해되고 `**`·`##` 기호가 남지 않는 것을 확인했습니다.
- 라이트·다크 두 테마의 본문/보조/약한 텍스트와 신호색 6쌍을 배경과 카드 양쪽에
  대해 WCAG 대비로 계산해 모두 4.5:1 이상임을 확인했습니다(최저 5.07:1). 사용자
  카드 본문, 근거 칩, 전송 버튼, 각주 hover 같은 반전 조합도 함께 확인했습니다.
- Codex가 제안한 보조색 `#397A73`은 연한 배경의 칩에서 4.30:1이라 `#2F6B64`로
  약간 어둡게 조정했습니다(5.31:1).
- CSS 클래스와 JSX 사용처를 교차 검증해 남은 죽은 스타일이 없음을 확인했습니다.
  세리프·모노 참조가 전부 사라진 것도 확인했습니다.
- 첫 화면 SSR에서 `data-evidence="false"`이고 근거 패널이 렌더되지 않는 것을
  확인했습니다.
- Pretendard CDN 응답 200을 확인했습니다. 실패해도 시스템 산세리프로 대체됩니다.
- 브라우저 렌더링(레이아웃, 라이트/다크 전환, 반응형)은 아직 눈으로 확인하지
  않았습니다.

## 지운 기록

한때 왼쪽에 `analyze → tools → generate` 진행 레일과 도구 호출 로그, `route`,
실행 시간 지표를 두었습니다. LangGraph 동작을 그대로 드러내는 화면이었지만
실사용자에게는 읽을 이유가 없는 정보라 걷어냈습니다. 되살릴 일이 생기면 SSE의
`status.tools`와 `result.tools`/`route`/`execution_seconds`를 다시 쓰면 됩니다 —
API는 지금도 전부 내려 주고 있습니다.

## 확인 중 알게 된 것

**Agent 답변은 Markdown으로 옵니다.** `##`, `**강조**`, 목록이 그대로 들어 있어서
평문으로 그리면 기호가 노출됩니다. 그래서 이 랩은 의존성 없이
`lib/answer-format.ts`에서 제목·목록·문단·강조만 처리하는 작은 파서를 두고
법령 문서에 가까운 위계로 조판합니다.

**`[S1]` 인용 표기는 현재 나오지 않습니다.** backend는 조문마다 `source_id`를
붙여 내려 주지만(`agent/tools.py`), 답변 생성 프롬프트가 그 ID로 인용하라고
지시하지 않아 실제 답변에는 표기가 없습니다. 그래서 본문 근거 칩과 카드 강조
연동은 코드에는 있지만 지금은 동작하지 않는 상태입니다. `agent/model.py`의
지침에 인용 규칙을 한 줄 추가하면 바로 살아납니다. (이 랩에서는 `src/`를
건드리지 않았습니다.)
