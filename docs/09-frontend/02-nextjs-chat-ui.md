# Next.js 상담 UI POC

- 작성일: 2026-07-28
- 현재 단계: 프론트 UI 기준선

## 왜 `localhost:3000`을 사용하는가

Next.js 개발 서버의 기본 포트가 `3000`이므로 별도 설정 없이 공식 기본 흐름을
사용했다. FastAPI의 `8000`, 삭제 전 Streamlit의 `8501`과도 겹치지 않아 각 서버의
역할을 주소만으로 구분하기 쉽다. `localhost`는 현재 컴퓨터 안에서만 접근하는
루프백 주소라서 로컬 학습·검증 목적에도 맞는다.

포트를 바꿔야 할 때는 다음처럼 실행할 수 있다.

```bash
npm run dev -- -p 3100
```

## 현재 구현 범위

`frontend/`는 기존 Streamlit 화면을 대체하기 위해 만든 Next.js App Router 기반
상담 UI다. 다음 동작을 제공한다.

- 직접 질문 입력과 최대 500자 제한
- 예시 질문을 눌러 입력창 채우기
- 빈 질문·답변 생성 중 중복 전송 방지
- Enter 전송과 Shift+Enter 줄바꿈
- 사용자 질문과 스트리밍 답변 표시
- 긴 답변 생성 중 대화 목록의 맨 아래 자동 추적
- 화면 높이에 맞춰 확장되는 반응형 상담 영역
- 금융 보호 방패와 상담 로봇을 결합한 통합 브랜드 심볼
- FastAPI 연결 실패 메시지

화면은 따뜻한 종이색 바탕, 먹색 경계선, 짙은 녹색 신호색으로 구성한다. 입력·로딩·
오류 상태에서도 같은 색과 문서형 번호 체계를 유지한다.

## 실행 방법

처음 한 번 `frontend/`의 의존성을 설치하고 개발 서버를 실행한다.

```bash
cd frontend
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 연다. UI 레이아웃과 질문 입력은 Next.js
서버만으로 확인할 수 있다. 실제 답변을 받으려면 별도 터미널에서 Ollama와 FastAPI도
실행되어 있어야 한다.

```bash
uv run fastapi dev
```

FastAPI는 `http://127.0.0.1:8000`, Next.js는 `http://localhost:3000`을 사용한다.

배포와 유사한 실행은 아래 순서로 확인한다.

```bash
cd frontend
npm run build
npm run start
```

## 서버 연결

브라우저는 같은 출처인 `POST /api/chat`을 호출한다. Next.js route handler가 질문을
FastAPI의 `POST /ask-rag/stream`으로 전달하고 텍스트 스트림을 그대로 브라우저에
돌려준다. 따라서 FastAPI에 CORS 설정을 추가하지 않고도 두 로컬 서버를 연결한다.

FastAPI 주소는 서버 환경 변수 `CHATBOT_API_URL`로 바꿀 수 있으며 기본값은
`http://127.0.0.1:8000`이다.

## 입력 불가 개선 기록

### 원인

첫 POC의 질문 영역은 실제 입력 요소가 아닌 `<span>`이었고, 전송 버튼에는
`disabled`가 고정되어 있었다. 정적 레이아웃을 먼저 확인하기 위한 의도였지만,
화면만 보면 입력 가능한 상담 UI로 오해할 수 있었다.

### 관찰

- 질문 영역을 눌러도 커서가 생기지 않았다.
- 키보드 입력과 예시 질문 선택이 상태에 반영되지 않았다.
- 전송 버튼이 항상 비활성 상태였다.

### 개선 작업

- 페이지를 client component로 전환하고 제어형 `<textarea>`를 추가했다.
- 예시 질문, Enter 전송, Shift+Enter 줄바꿈을 연결했다.
- 빈 값과 전송 중에는 버튼을 비활성화했다.
- Next.js 프록시와 텍스트 스트림 렌더링, 연결 오류 표시를 추가했다.

### 결과

질문을 직접 입력하거나 예시 질문으로 채울 수 있고, 전송 시 사용자 메시지가 화면에
추가된다. FastAPI가 실행 중이면 답변 조각이 도착하는 순서대로 표시되며, 실행되지
않았으면 확인할 서버를 알려주는 오류가 입력창 아래에 나타난다.

브라우저에서 직접 입력, 예시 질문 선택, 전송 중 입력 잠금, 실제 FastAPI 스트리밍
답변 완료를 확인했다. 빈 질문을 프록시에 직접 요청한 경우에는 `400 Bad Request`와
`질문을 입력해 주세요.`를 반환했으며, production build와 TypeScript 검사도 통과했다.

## 긴 대화와 브랜드 개선

### 관찰

- 대화 목록의 최대 높이가 `280px`로 고정되어 긴 상담에서 문맥을 보기 어려웠다.
- 답변 조각이 추가돼도 사용자가 직접 스크롤하지 않으면 최신 문장이 화면 아래로
  벗어날 수 있었다.
- 헤더의 `§`와 상담봇의 `안` 문자가 서로 다른 인상을 주어 하나의 상담 주체처럼
  느껴지지 않았다.

### 개선 작업

- 상담 카드가 데스크톱에서는 최대 `760px`, 모바일에서는 화면 높이에 맞춰 커지도록
  반응형 높이를 적용했다.
- 메시지 목록이 상담 카드의 남은 공간을 사용하도록 flex layout으로 바꿨다.
- 메시지와 스트리밍 조각이 추가될 때마다 목록의 전체 높이를 기준으로 맨 아래를
  따라가도록 자동 스크롤을 추가했다.
- 첫 질문 뒤에는 예시 질문을 접어 실제 대화 공간을 확보했다.
- 제공된 이미지의 녹색·아이보리 인상을 참고해 방패, 말풍선, 로봇 얼굴을 결합한
  독자 심볼을 만들고 헤더·favicon·상담봇 프로필에 함께 적용했다.

### 결과

짧은 대화에서는 시작 질문을 바로 고를 수 있고, 긴 답변에서는 입력창을 고정한 채
최신 답변이 대화 영역의 맨 아래에 계속 보인다. 화면 폭이 좁아지면 상담 카드가
세로 화면 대부분을 사용하며, 같은 심볼이 서비스와 상담봇의 정체성을 연결한다.

브라우저에서 답변 두 건을 누적한 데스크톱 대화는 하단 거리 `0px`, 모바일 긴 답변은
반올림 오차를 포함해 `0.5px`를 유지했다. 데스크톱과 모바일 크기를 오간 뒤에도
ResizeObserver가 목록을 다시 맞췄으며 콘솔 오류는 없었다. 최종 로고 파일은
`frontend/public/financial-guardian.png`에 보관한다.

## UI 기준선과 Streamlit 정리

현재 `frontend/`를 프론트 UI 기준선으로 사용한다. 질문 입력, 스트리밍 답변, 오류
안내, 반응형 화면과 자동 스크롤까지 확인했으므로 이후에는 디자인과 미세 조정만
반영한다.

Next.js가 기존 UI 역할을 모두 대체하고 Python 실행 코드에서도 참조하지 않아
`streamlit_app.py`, `.streamlit/config.toml`, Streamlit 의존성을 제거했다. 이전
구현 기록만 [archive/01-streamlit-chat-ui.md](archive/01-streamlit-chat-ui.md)에
보관한다.
