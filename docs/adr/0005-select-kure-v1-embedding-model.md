# ADR 0005. 임베딩 모델로 KURE-v1을 선택한다

- 상태: Accepted
- 날짜: 2026-07-06
- 구현 상태: 인덱싱 완료 (청크 322개)

## 배경

청크 322개(ADR 0004 corpus, 조문 보존 청킹)를 벡터로 바꿔 검색하는
임베딩 모델이 필요하다. 제약: 무료 오픈소스, 상업 이용 가능 라이선스,
M2 Pro 16GB 로컬 구동, 한국어 검색 성능. 선정은 벤치마크 인용이 아니라
우리 corpus·평가 질문으로 실측해 결정한다.

## 고려한 선택지

같은 체급(0.55~0.6B, 1024차원)의 후보 4종을 실측 비교했다.

1. intfloat/multilingual-e5-large — 다국어 기준선, 512토큰, MIT
2. BAAI/bge-m3 — 다국어, 8192토큰, MIT (KURE의 원본 모델)
3. nlpai-lab/KURE-v1 — bge-m3의 한국어 검색 파인튜닝, 8192토큰, MIT
4. Qwen/Qwen3-Embedding-0.6B — 최신 세대, 32K토큰, Apache 2.0

제외한 후보: jina-embeddings-v3(CC-BY-NC, 상업 불가),
OpenAI·Cohere·Upstage(유료 API — 무료·로컬 제약 위반), 7B급 임베딩(로컬
메모리 과다), embeddinggemma(자체 사용 제한 약관), KoE5·BGE-m3-ko(KURE와
같은 한국어 파인튜닝 계열이라 대표 1종만 비교).

## 결정

`nlpai-lab/KURE-v1`을 임베딩 모델로 선택한다. 실행은
sentence-transformers(MPS)이며, 동일성 원칙에 따라 인덱싱과 질의 임베딩에
모델 artifact·전처리·pooling·정규화·차원·실행 backend를 완전히 동일하게
사용한다.

## 결정 이유

평가 질문 15개(gold 조문을 원문 대조로 확정, 조문 단위 집계)로 측정한
결과 KURE-v1이 MRR 0.559, Hit@1 0.400, Hit@5 0.800, Recall@5 0.700으로
전 지표 최상위였다. 원본 bge-m3(MRR 0.497, Hit@1 0.267)보다 높았는데,
이는 KURE의 추가 한국어 검색 파인튜닝 이후 관찰된 차이이며 데이터·학습
방법 각각의 순수 효과를 분리한 결과는 아니다. 실험 재현은
`scripts/compare_embeddings.py`(gold 라벨 포함).

- e5-large는 512토큰 한계로 청크 322개 중 54개(17%)가 절단됐고 검색
  품질도 낮았다(MRR 0.448). 8192토큰인 KURE-v1은 최장 청크(608토큰)도
  절단 없이 수용한다 — 현재 청킹(1,000자/overlap 100)과 입력 한도의
  호환성을 확인한 것이며, 이 청킹이 검색 품질상 최적이라는 의미는
  아니다.
- Qwen3-Embedding-0.6B는 이 평가에서 최하위(MRR 0.444)였고 인덱싱도 가장
  느렸다(84초, causal LM 구조의 last-token pooling).
- MIT 라이선스, 로컬 상주 약 2.3GB로 제약을 모두 충족한다.

## 감수하는 단점

- Ollama 공식 라이브러리에 없어(bge-m3만 존재) RAG 서빙에서는 질의 임베딩용
  sentence-transformers를 FastAPI 프로세스에 상주시켜야 한다. 로드 수십
  초·상주 약 2.3GB는 수용 가능하다. TEI 같은 별도 임베딩 서버로 분리하는
  선택지는 남아 있으나 현 단계에서는 과하다.
- 평가 표본이 15문항으로 작아 절대 성능이 아닌 후보 간 상대 비교
  근거다. 전체 기준선은 평가 질문 전체 실행(세션⑩)에서 측정한다.
- 한국어 특화 파인튜닝이 비한국어 질의 성능을 낮췄을 수 있으나, 이
  서비스의 질의는 한국어로 한정된다.

## 검증 계획

이 모델로 322개 청크를 인덱싱했고, 평가 질문 15개에서 Chroma와 브루트포스
검색의 top-5 조문이 모두 일치하는지 확인했다. 전체 RAG 기준선은 평가 질문
24개로 기록한다. 모델·backend를 바꾸는 경우 인덱스를 반드시 재생성한다.
