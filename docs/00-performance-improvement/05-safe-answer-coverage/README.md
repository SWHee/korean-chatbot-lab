# 안전한 답변 도달률 개선

- 작성일: 2026-08-02
- 상태: 문제와 개선 방향 정리, 구현 전

## 관찰과 기준선

금융상품과 법령 안내는 음악 추천보다 잘못된 답변의 비용이 크다. 근거가 없는 보호
여부, 가입 조건이나 금리를 확신해서 안내하면 사용자의 금전적 판단에 영향을 줄 수
있다. 따라서 현재 RAG가 직접 근거를 찾지 못했을 때 추측하지 않는 원칙은 유지해야
한다.

그러나 안전하다는 이유만으로 비슷한 질문까지 모두 같은 거절 안내로 끝내는 것도 좋은
금융 상담 경험은 아니다. 실제 UI에서는 법률 약칭, 오타 또는 문장 표현이 조금만
달라져도 `can_answer=false`가 되었고, 사용자는 무엇을 바꿔 물어야 하는지 알기
어려웠다. 상세 사례는
[Agent 확장 전 사용자 경험 점검](../../07-langgraph-agent/00-user-experience-before-agent-expansion.md)에
기록했다.

현재의 핵심 한계는 안전장치 자체가 아니라 다음 상황을 하나의 `답변 불가`로 처리하는
것이다.

| 상황 | 사용자에게 필요한 동작 |
| --- | --- |
| 질문이 모호함 | 답을 좁힐 조건 하나를 질문 |
| 법률 약칭·오타 | 표현을 보정하거나 확인 질문 |
| 검색이 직접 근거를 놓침 | 질문 재작성이나 다른 검색 방식으로 재시도 |
| 일부만 근거가 있음 | 확인된 범위만 답하고 한계를 구분 |
| 상품 정보가 필요한 질문 | 법령 RAG가 거절하지 않고 Finlife 경로로 전환 |
| 실제 지원 범위 밖 | 지원 범위와 다시 물을 수 있는 예시 안내 |

## 후보와 선택 근거

`can_answer` 기준을 느슨하게 하면 답변 수는 늘지만 근거 밖 주장을 허용할 위험이 있다.
반대로 현재의 이진 판단과 고정 안내만 유지하면 안전하지만, 해결할 수 있는 질문까지
거절하는 경험이 반복된다.

따라서 목표는 거절을 줄이는 것이 아니라 **근거 없는 답변을 늘리지 않으면서 사용자가
도움이 되는 답에 도달하는 비율을 높이는 것**이다. 이를 위해 최종 응답을 다음처럼
단계적으로 나눈다.

```text
직접 근거 있음 → 근거 기반 답변
조건이 부족함 → clarify로 가장 필요한 조건 질문
검색 표현 문제 → 정규화·재작성·검색 보완 후 재시도
일부 근거만 있음 → 확인된 내용과 확인하지 못한 범위 분리
상품 질문 → Finlife 조회와 명시적인 비교 기준 안내
지원 범위 밖 → 가능한 질문 예시와 함께 범위 안내
```

한 번의 Prompt 수정으로 모두 해결하지 않는다. 질문 분석과 `clarify`는 Agent
Workflow에서, 약칭·오타와 검색 누락은 검색 견고성 개선에서, 부분 답변은 근거 상태를
구분할 수 있을 때 각각 작은 단위로 검증한다. 그전까지 현재의 보수적인 고정 안내는
안전 기준선으로 유지한다.

## 비교 기준

이 축은 단순히 답변을 많이 생성했는지로 평가하지 않는다.

| 지표 | 확인할 내용 |
| --- | --- |
| 근거 없는 주장 비율 | 안전성을 낮춰 답변 수만 늘리지 않았는지 |
| 불필요한 거절 비율 | 근거나 지원 경로가 있는데도 답하지 못했는지 |
| 유효 답변 도달률 | 답변·추가 질문을 거쳐 사용자가 도움을 받았는지 |
| 추가 질문 완료율 | `clarify`가 대화를 막지 않고 조건을 채웠는지 |
| 경로별 응답 시간 | 검색 재시도와 분기가 UX를 지나치게 늦추지 않는지 |

현재는 문제와 기준만 기록한다. Routed Workflow와 멀티턴 `clarify`가 연결된 뒤 대표
질문을 추가하고, 검색 개선은
[법령 검색 견고성 개선 지도](../04-retrieval-robustness/README.md)의 순서대로 한 방법씩
비교한다.
