# 생성 토큰 상한 이해

- 작성일: 2026-07-23
- 상태: 설정 분석, 변경 없음
- 현재 설정: `MAX_NEW_TOKENS = 1024`

`MAX_NEW_TOKENS`가 응답 시간과 어떤 관계가 있는지 궁금해서 현재 출력 길이와 함께
확인해봤습니다. 이 값은 모델이 답변으로 생성할 수 있는 **최대 토큰 수**입니다.
Ollama 요청에서는 `num_predict`로 전달되며, 모델이 답변을 끝냈다고 판단하면 상한에
도달하기 전에도 생성이 끝납니다.

이 값은 질문과 검색 문맥을 담는 입력 길이가 아닙니다. 입력과 출력은 모델의 전체
context 안에서 함께 사용되므로 다음 세 값을 구분해야 합니다.

| 항목 | 의미 |
| --- | --- |
| 입력 토큰 | prompt, 질문, 검색된 법령 조문 |
| 생성 토큰 | 모델이 답변으로 만든 토큰 |
| context 길이 | 모델이 한 요청에서 다룰 수 있는 입력과 출력의 전체 범위 |

현재 Ollama 생성기는 context 4,096과 생성 상한 1,024를 사용합니다. 법령 조문을
길게 전달하면 입력이 context의 많은 부분을 차지합니다. 따라서 생성 상한만 크게
늘린다고 항상 긴 답변을 끝까지 만들 수 있는 것은 아니었습니다.

## 값을 늘릴 때

장점:

- 긴 설명과 여러 법령 근거를 끝까지 작성할 여유가 생깁니다.
- 답변이 문장 중간이나 출처 설명 전에 잘릴 가능성이 줄어듭니다.

주의점:

- 모델이 실제로 더 길게 답하면 전체 응답 시간과 배터리 사용량이 늘어납니다.
- 불필요한 반복이나 장황한 답변도 길어질 수 있습니다.
- 긴 출력은 context와 메모리를 더 사용합니다.

처음에는 상한을 늘리면 첫 토큰부터 느려지는지 궁금했습니다. 하지만 같은 입력에서
모델이 같은 지점에 답변을 끝낸다면 실행 시간도 거의 달라지지 않습니다. 실제 차이는
모델이 기존 상한을 넘어 계속 답변을 만들 때 커집니다.

## 값을 줄일 때

장점:

- 최악의 생성 시간과 답변 길이를 제한하기 쉽습니다.
- 짧고 일정한 답변을 유도하고 평가 실행 시간을 줄일 수 있습니다.
- 로컬 실행의 전력과 메모리 사용을 줄이는 데 도움이 됩니다.

주의점:

- 상한이 너무 작으면 문장, 법령 인용 또는 주의사항이 중간에 끊길 수 있습니다.
- 답변이 짧아진 것을 속도 개선으로만 판단하면 필요한 정보가 빠질 수 있습니다.

## 현재 프로젝트의 적용 원칙

Agent 기능과 평가 기준선을 만들기 전에는 생성 모델과 1,024토큰 상한을 바꾸지
않기로 했습니다. 이후 대표 질문으로 다음 값을 함께 확인한 뒤 상한을 조정할
예정입니다.

- 실제 생성 토큰 수
- 생성 종료 이유
- 첫 토큰 시간과 전체 응답 시간
- 답변이 끝까지 완성되었는지
- 필요한 법령명·조문번호·시행일이 포함되었는지

상한을 줄일 때는 한 번에 한 값만 바꾸고 같은 질문과 평가 기준을 사용하려고 합니다.
속도가 빨라져도 답변이 잘리거나 필요한 근거가 빠지면 개선이라고 보기 어렵기
때문입니다.

## 현재 기준선 실측

LangChain v1 기준선 24문항의 답변을 Qwen3 토크나이저로 다시 세어봤습니다.
Ollama가 응답할 때 기록한 원본 `eval_count`가 아니므로 실제 값과는 조금 다를 수
있습니다.

| 항목 | 결과 |
| --- | ---: |
| 최소 출력 | 232토큰 |
| 중앙값 출력 | 516토큰 |
| p90 출력 | 676토큰 |
| 최대 출력 | 1,024토큰 |
| 512토큰 이상 | 13문항 |
| 768토큰 이상 | 2문항 |
| 1,024토큰 도달 | 1문항 |

1,024토큰과 1,022토큰을 생성한 답변은 모두 문장 중간에서 끝났습니다. 이 결과를
보니 512나 768로 상한을 바로 줄이면 더 많은 답변이 잘릴 가능성이 커 보였습니다.

재토큰화한 prompt 본문과 답변을 합친 길이는 24문항 모두 4,096토큰보다 작았습니다.
합계의 중앙값은 3,182토큰, p90은 3,655토큰, 최댓값은 3,842토큰이었습니다. 실제
요청에는 chat template의 특수 토큰도 들어가므로 이 값은 context 여유를 판단하는
근삿값입니다.

그래서 현재 설정을 바로 줄이지 않기로 했습니다. Agent 기준선을 만든 뒤 처음
비교해볼 후보는 `1,280`토큰입니다. 현재 상한보다 25%만 늘려 잘린 두 답변이
완성되는지 확인하기 위한 값입니다. 다만 긴 prompt와 긴 답변이 동시에 나오면
4,096 context를 넘을 수 있습니다. 전체 설정으로 바로 확정하지 않고 대표 장문 질문
두 개로 먼저 확인한 뒤, 전체 응답 시간과 답변 완성도를 함께 비교할 예정입니다.
