# 법령 검색 견고성 개선 지도

- 작성일: 2026-08-02
- 상태: 개선 후보와 실험 순서 정리, 개별 구현 전

이 문서는 여러 검색 개선을 한꺼번에 적용한 기록이 아니라, 앞으로 만들 개별 실험
문서의 짧은 목차다. 실제 작업을 시작할 때 질문 정규화, Hybrid Search, Reranker와
부모-자식 검색을 각각 다른 문서로 기록한다.

## 관찰

법률명을 정확히 쓰지 않거나 생활 표현으로 질문하면 직접 근거를 놓쳤다.

```text
금융소비자보호법       → 실패
금융소비자보호범       → 실패
금융소비자보호법이 뭐냐고 → 성공
은행 파산 시 예금 보호 한도 → 정답 조문 검색 실패
```

현재 검색은 사용자 문장 전체를 KURE-v1으로 임베딩한 뒤 Chroma의 가까운 청크를
선택한다. 법률명·조문 제목의 정확한 단어, 오타와 질문 의도를 따로 처리하지 않는다.
`top_k`만 늘리면 관련 없는 조문도 함께 늘 수 있어 첫 해결책으로 삼지 않는다.

## 개선 후보와 판단

| 후보 | 해결하는 문제 | 현재 판단 |
| --- | --- | --- |
| UI 키워드와 공식 법률명 함께 표시 | 화면과 검색 범위의 오해 | 데모 전 우선 확인 |
| 약칭·오타 정규화 | `금소법`, `보호범` 같은 표현 | 작은 규칙과 질문 분석을 함께 검토 |
| 검색 질문 재작성 | 생활 표현과 법률 용어의 차이 | 질문 분석 Node 연결 후 검증 |
| Hybrid Search | 정확한 법률명·조문 제목과 의미 검색 결합 | Agent POC 뒤 첫 검색 실험 후보 |
| Reranker | 후보 중 직접 근거를 상위로 이동 | Hybrid 후보가 만들어진 뒤 비교 |
| 부모-자식 검색 | 짧은 청크로 찾고 전체 조문을 답변 근거로 사용 | 청킹 비교 Dataset을 고정한 뒤 실험 |
| 안내 세분화 | 모호함·오타·검색 실패가 같은 문구로 보이는 문제 | Agent route와 함께 적용 검토 |

법령을 관계형 DB나 Graph DB에 저장하는 방법도 후보지만, 저장소를 바꾸는 것만으로
자연어 검색이 좋아지지는 않는다. 조문 간 인용 관계를 따라가는 요구가 확인될 때
Graph DB를 검토하고, 현재의 법률명·본문 검색 문제는 먼저 검색 방식으로 비교한다.

## 적용 순서

1. Agent Workflow에서 질문 분석과 실제 RAG 경로 연결
2. 약칭·오타·짧은 질문을 포함한 작은 견고성 테스트 추가
3. UI 키워드와 backend가 같은 표현을 지원하는지 확인
4. 같은 질문으로 Vector Search와 Hybrid Search 비교
5. 필요할 때 Reranker와 부모-자식 검색을 하나씩 추가 비교

비교할 때는 검색 Recall·Precision뿐 아니라 사용자가 답을 받았는지, 잘못된 단정을
막았는지와 추가 latency를 함께 본다. Agent POC를 먼저 진행하되, 공개 시연 전에는
UI가 제시한 표현과 대표 오타가 실제로 처리되는지 반드시 확인한다.
