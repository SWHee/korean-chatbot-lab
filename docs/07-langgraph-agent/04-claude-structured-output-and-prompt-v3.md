# Claude Structured Output과 시스템 Prompt v3

- 작성일: 2026-08-02
- 상태: 구현·단위 검증 완료, UI·24문항 비교 전

## 배경

기존 출력 형식은 Ollama가 구조화 JSON을 안정적으로 만들도록 Prompt와 전용 배열을
함께 사용했다. 현재 주 생성기는 JSON Schema를 직접 지원하는 Claude API다. 따라서
형식 지시를 반복하기보다 금융 상담 답변의 정확성과 말투에 집중시키는 편이 낫다.

이 프로젝트의 답변 기준은 다음과 같다.

- **신뢰**: 근거가 있는 내용과 확인할 수 없는 범위를 분명히 구분
- **친절**: 법률 용어를 쉬운 한국어 존댓말로 설명
- **믿음**: 과장된 확신 대신 근거와 다음 확인 방법 제공
- **일관성**: 차분한 UI와 어울리는 답변 유지

## 변경

`RagAnswer`의 이름 있는 세 필드를 일반 응답과 스트리밍에서 함께 사용한다.

```text
can_answer → source_ids → answer
```

기존 `result: [can_answer, source_ids, answer]` 배열과 배열 순서 Prompt는 제거했다.
`can_answer=false`가 먼저 도착하면 고정 안내로 전환하는 동작은 그대로 유지한다.

시스템 Prompt v3는 다음에 집중한다.

- 결론을 먼저 제시하고 이유와 중요한 조건 설명
- 법률 용어를 일상적인 표현으로 풀이
- 필요한 경우에만 다음 확인 사항 안내
- 같은 설명과 화면에 따로 표시되는 출처 정보 반복 방지
- 근거 밖 추측과 개별 상품 보호 여부 단정 금지

Claude API가 정상 완료 응답의 schema를 강제하므로 `JSON만 반환`하라는 지시는
제거했다. Pydantic과 Python의 근거 ID 검증은 형식과 안전을 담당하므로 유지한다.

## 확인할 결과

단위 테스트에서는 정상 답변 스트리밍, 존재하지 않는 출처 차단, `false` 조기 전환을
확인했다. 다음 수동 확인에서는 답변이 충분히 친절한지, 설명이 지나치게 짧거나
반복되지 않는지 살펴본다. 통과하면 기존 24문항으로 Faithfulness, 답변 길이,
생성 시간과 상담 말투를 이전 Prompt와 비교한다.
