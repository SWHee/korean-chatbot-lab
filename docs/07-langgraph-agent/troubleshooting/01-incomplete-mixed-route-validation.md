# 불완전한 mixed 질문의 500 오류

## 증상

Swagger의 `/ask-workflow`에 다음 질문을 보냈을 때 HTTP 500이 발생했다.

```text
예금 상품 추천 및 예금자 보호법도 설명
```

Trace에는 다음 Pydantic 검증 오류가 남았다.

```text
mixed route requires law_question and complete product_filters
```

## 원인

질문에는 상품 추천과 법령 설명 의도가 함께 있어 모델이 `mixed`를 선택했다. 동시에
예금 기간이 없다고 판단해 `term_months=None`, `missing_fields`, 추가 질문도 반환했다.

현재 계약에서 `mixed`는 법령 질문과 완성된 상품 조건이 모두 있어 즉시 두 조회를
실행할 수 있는 상태다. 따라서 하나의 결과가 `mixed`와 `clarify` 의미를 동시에 가져
검증에 실패했다. 이 예외를 사용자 응답으로 바꾸는 경계가 없어 HTTP 500까지 전파됐다.

Structured Output은 필드 이름과 자료형을 맞추는 데 도움을 주지만, `mixed`인데 상품
조건은 미완성인 것과 같은 필드 사이의 의미 충돌까지 보장하지는 않는다.

## 고려한 선택지

| 선택지 | 판단 |
| --- | --- |
| Prompt에 우선순위만 추가 | 발생 가능성은 낮추지만 모델 출력만으로 안정성을 보장하기 어려움 |
| 충돌 결과를 모두 오류로 거부 | 내부 계약은 엄격하지만 정상적인 사용자 질문이 500으로 끝남 |
| Prompt와 Python 정규화 함께 적용 | 모델에는 의도를 알리고, 알려진 충돌은 코드에서 안전하게 처리 가능 |

세 번째 방법을 선택했다. 상품 조건이 하나라도 부족하면 법령 의도가 함께 있더라도
먼저 `clarify`로 전환한다. 모델이 추가 질문 문구를 만들지 못한 경우에는 누락된
필드에 따라 짧은 질문을 코드에서 제공한다. 법령 질문은 분석 결과에 보존해 이후
멀티턴 상태를 연결할 때 다시 사용할 수 있게 한다.

## 적용과 확인

- 질문 분석 Prompt에서 `clarify`를 불완전한 `mixed`보다 우선하도록 명시
- `QuestionAnalysis` 검증 전에 불완전한 `mixed`를 `clarify`로 정규화
- 실제 Swagger 질문과 당시 분석 결과를 재현하는 Workflow 회귀 테스트 추가
- 추가 질문이 비어 있는 분석 결과에도 기본 질문을 만드는 모델 검증 테스트 추가

수정 전 두 테스트는 같은 Pydantic 오류로 실패했다. 수정 후에는 조회 Node에 진입하지
않고 `몇 개월 동안 가입할 예금을 찾으시나요?`라는 추가 질문으로 정상 종료했다.

이번 보완은 알려진 route 충돌을 다룬다. 외부 모델 장애나 전혀 다른 스키마 오류까지
모두 숨기는 범용 예외 처리는 아니며, 실제 사례가 확인될 때 별도 실패 계약으로 다룬다.
