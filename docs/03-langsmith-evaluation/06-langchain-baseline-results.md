# LangChain v1 기준선 결과

- 실행일: 2026-07-20
- Dataset: `korean-chatbot-rag-v1-dev` 24문항
- Dataset 버전: `rag-v1-dev`
- 법령 corpus snapshot: `2026-07-06`
- 생성 모델: `qwen3:4b-instruct-2507-q4_K_M`
- 임베딩 모델: `nlpai-lab/KURE-v1`
- 검색 설정: 조문 단위 상위 5개
- Judge: `gemini-3.5-flash`, Faithfulness 세 단계 평가
- 실행 설정: `max_concurrency=1`

이 결과는 높은 성능을 주장하기 위한 최종 시험이 아니다. 현재 LangChain RAG를
LangGraph로 옮긴 뒤 같은 질문과 채점 기준으로 다시 비교하기 위한 개발 기준선이다.

## 기준선 Experiment

API 한도가 초기화된 뒤 24문항을 하나의 Experiment로 실행했다. RAG 실행과
검색·Faithfulness 평가에 오류가 없는 이 결과를 LangChain v1의 기준선으로 사용한다.

## 지표 읽는 법

- `precision_top_5`: 검색된 상위 5개 조문 중 정답 또는 보조 정답 조문의 비율
- `recall_top_5`: 필수 정답 조문 중 상위 5개에서 찾은 조문의 비율
- `faithfulness`: 생성 답변의 사실 주장이 실제 검색 문맥에 근거하는지 보는 점수
- `N/A`: 현재 법령 corpus에서 정답 조문이나 Faithfulness 대상을 정하지 않은 문항

Precision과 Recall은 조문 ID를 직접 비교한 프로젝트 지표다. Faithfulness도 현재
프로젝트가 정한 `0`, `0.5`, `1` 세 단계 Judge 점수다. 정답성이나 답변 완성도를
Faithfulness 하나로 판단하지 않는다.

## 집계와 관찰

| 지표 | 결과 |
| --- | ---: |
| `precision_top_5` | 0.280, 15문항 |
| `recall_top_5` | 0.711, 15문항 |
| `faithfulness` | 0.733, 15문항 |
| RAG 실행 시간 | 평균 18.75초, 최소 10.84초, 최대 29.21초 |

Recall보다 Precision이 낮다. 필수 조문을 찾는 경우는 많지만 관련성이 낮은 조문도
함께 들어오는 경향이 있다는 뜻이다. A7·A9·C1처럼 필요한 조문을 찾고도 생성 모델이
뜻을 반대로 해석한 사례도 있다. 반대로 A1·A11처럼 답을 충분히 하지 못했어도 검색
문맥 밖 내용을 만들지 않아 Faithfulness가 높게 나온 사례가 있다.

검색 점수는 앞선 분할 실행과 같았지만 생성 답변과 Judge 점수는 일부 달랐다. 로컬
생성 결과와 LLM 평가는 실행마다 달라질 수 있으므로, 이후 LangGraph 비교에서는 이
단일 24문항 Experiment를 기준으로 삼는다.

B1은 Faithfulness의 범위도 보여준다. 답변이 검색 문맥에 포함된 시행일을 사용해
Faithfulness는 1점이지만, Dataset의 기대 답변에 적힌 시행령 시행일과는 다르다.
따라서 현재 점수를 정답률로 읽지 않고, 답변 정확성 평가는 후속 evaluator 후보로
남긴다.

따라서 다음 비교에서는 검색 품질과 생성 충실도를 따로 본다. LangGraph로 실행 구조만
옮긴 직후에는 같은 Dataset, top 5, prompt, 모델, Judge를 유지하고 이 기준선보다
나빠진 문항이 있는지 확인한다.

## 기준선의 한계

현재 24문항은 임베딩 모델 선택과 검색 검증에 사용한 개발 Dataset이다. 독립적인
최종 성능 수치로 사용하지 않는다. 또한 Faithfulness는 답변이 질문을 충분히
해결했는지 평가하지 않는다. 이후 상품 API와 질문 분기가 추가되면 D 유형의 기대
동작과 평가 기준은 새 Dataset 버전에서 변경한다.
