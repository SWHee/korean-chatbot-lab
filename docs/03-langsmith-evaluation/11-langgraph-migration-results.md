# LangChain RAG를 LangGraph로 옮긴 뒤 평가해본 결과

- 작성일: 2026-07-23
- LangChain 기준선: `rag-v1-baseline-12f1244c`
- LangGraph 비교 실행: `rag-graph-v1-baseline-859d35a9`
- Dataset: `korean-chatbot-rag-v1-dev` 24문항

## 무엇을 확인하려 했는지

기존 LangChain RAG의 검색과 생성 흐름을 LangGraph의 `retrieve → generate`
노드로 옮겼습니다. 코드는 정상적으로 실행됐지만, 구조를 바꾸는 과정에서 기존 검색
결과나 답변 흐름이 달라지지는 않았는지 같은 24문항으로 확인해보고 싶었습니다.

그래프 구조만 비교하기 위해 Dataset, 법령 corpus, 임베딩 모델, 검색 상위 5개,
생성 모델, prompt와 Judge는 기존 기준선과 똑같이 유지했습니다.

```text
LangChain
질문 → Retriever → prompt | model | parser → 답변

LangGraph
START → retrieve → generate → END
                    └─ 기존 prompt | model | parser 재사용
```

## 직접 비교해본 결과

| 항목 | LangChain | LangGraph |
| --- | ---: | ---: |
| 실행 문항 | 24 | 24 |
| 실행 오류 | 0 | 0 |
| `precision_top_5` | 0.280 | 0.280 |
| `recall_top_5` | 0.711 | 0.711 |
| `faithfulness` | 0.733 | 0.700 |
| 평균 실행 시간 | 18.75초 | 18.35초 |
| 중앙 실행 시간 | 18.64초 | 17.28초 |
| 최소 실행 시간 | 10.84초 | 10.51초 |
| 최대 실행 시간 | 29.21초 | 29.98초 |

검색 Precision과 Recall은 전환 전후에 똑같이 나왔습니다. 같은 검색 함수와
벡터스토어를 재사용한 결과가 실제 평가 지표에서도 유지된 것을 확인했습니다. 적어도
검색 과정은 LangGraph로 옮기면서 달라지지 않았다고 볼 수 있었습니다.

Faithfulness는 0.733에서 0.700으로 조금 낮아졌습니다. 로컬 모델의 답변과 LLM
Judge 판정은 실행할 때마다 달라질 수 있고, A1에서는 Judge가 근거 밖 주장을 놓친
사례도 있었습니다. 이 차이만 보고 그래프 전환 때문에 답변 품질이 낮아졌다고
말하기는 어려웠습니다.

## 응답 시간이 조금 짧아 보인 이유

평균 실행 시간이 0.40초, 약 2.1% 줄어서 처음에는 그래프로 바꾼 효과인지
궁금했습니다. 하지만 그래프의 생성 노드는 여전히 같은 Qwen 모델과 LCEL 생성
체인을 호출합니다. LangGraph가 모델 추론 자체를 빠르게 만든 것은 아닙니다.

이번 실행에서는 다음 조건을 따로 고정하거나 기록하지 못했습니다.

- 질문별 실제 생성 토큰 수
- Ollama 모델 적재 시간
- prompt 처리 시간과 생성 시간
- 실행 당시 시스템 부하

이번에 FastAPI 서버를 켠 것만으로 Ollama 모델이 메모리에 적재되는 것은 아니라는
점도 처음 알게 되었습니다. 모델은 첫 생성 요청에서 적재되고, 별도 설정이 없다면
마지막 요청 뒤 기본 5분간 유지됩니다. 연속 평가에서는 앞선 문항 덕분에 다음 문항이
웜 상태에서 실행될 수 있지만, 이번 기록만으로 시간 차이의 원인을 하나로 확정할
수는 없었습니다.

따라서 이번 실행 시간은 전환 후 관찰값으로만 남깁니다. 구조 변경이 잘 됐는지는
작은 시간 차이보다 24문항에 실행 오류가 없었고 검색 지표가 동일했다는 점을 중심으로
확인했습니다.

## 이번 평가에서 확인한 것

24문항이 오류 없이 실행됐고 검색 지표도 기존 기준선과 같았습니다. 기존 RAG 동작을
`retrieve → generate` 그래프로 옮기는 1차 마이그레이션은 정상적으로
완료됐다고 보았습니다.

평가 답변을 살펴보면서 같은 결론을 반복하는 문제도 발견했습니다. 다음에는 그래프
구조와 검색 설정을 그대로 두고 간결화 Prompt 후보를 비교했습니다. 이 후보는
응답이 짧고 빨라졌지만 품질이 낮아 미채택했으며, 후속 방향은
[RAG Structured Output v2 설계](../05-performance-improvement/02-rag-response-reliability/03-structured-output-v2-design.md)에
기록했습니다.
