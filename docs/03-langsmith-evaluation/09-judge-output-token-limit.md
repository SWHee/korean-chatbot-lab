# Judge 출력 토큰 상한을 512로 둔 이유

- 작성일: 2026-07-23
- 적용 값: Gemini Judge `max_tokens=512`

## 처음 헷갈렸던 점

RAG 답변은 최대 1,024토큰인데 Judge는 512토큰으로 설정되어 있어서, Judge가
답변의 절반만 읽고 평가하는 것은 아닌지 궁금했습니다. 확인해보니 두 값은 서로 다른
모델 호출의 출력 상한이었습니다.

```text
Qwen
질문 + 검색 문맥 → RAG 답변 최대 1024토큰

Gemini Judge
질문 + 검색 문맥 + 완성된 RAG 답변 → 평가 결과 최대 512토큰
```

Judge의 `max_tokens`는 RAG 답변을 512토큰까지만 읽는다는 뜻이 아닙니다. Gemini가
평가 결과로 생성할 수 있는 최대 길이입니다. 질문, 검색 문맥과 완성된 RAG 답변은
Gemini의 입력 컨텍스트로 별도로 전달됩니다.

## 512로 정한 이유

현재 Judge가 출력하는 값은 다음 세 가지입니다.

- `score`: `0`, `0.5`, `1` 중 하나
- `reason`: 한국어 1~2문장, 최대 400자
- `issues`: 근거가 없거나 모순되는 주장, 최대 3개

이 정도 구조에는 512토큰이면 충분하다고 보았습니다. Qwen과 똑같이 1,024로
늘리더라도 평가에 필요한 정보가 더 생기는 것은 아니고, Judge가 불필요하게 길게
답할 여지만 커집니다.

512토큰이 실제로 부족하면 RAG 답변이 잘리는 것이 아니라 Judge의 JSON 출력이 끝나지
않아 파싱 오류가 날 수 있습니다. 지금까지 평가에서는 이런 오류가 없었으므로 현재
값을 유지합니다. 평가 필드를 늘리거나 파싱 오류가 반복될 때만 다시 조정할
예정입니다.
