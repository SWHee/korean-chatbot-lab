# RAG 답변 간결화 Prompt 실험과 미채택 결정

- 작성일: 2026-07-24
- 결정: 간결화 Prompt 후보 미채택
- 비교 기준선: `rag-graph-v1-baseline-859d35a9`
- 실험 실행: `RAG prompt V2 / 응답 품질 매우 안좋음`
- Dataset: `korean-chatbot-rag-v1-dev` 24문항

## 왜 비교했는지

기존 답변은 검색 근거가 부족할 때 같은 한계를 반복하고, 질문과 직접 관련이 없는
조문까지 설명해 길어지는 문제가 있었다. 간결화 Prompt 후보에서는 다음 두 동작을
분명하게
지시했다.

- 직접 답하는 근거가 있으면 결론과 근거 조문 제시
- 직접 답하는 근거가 없으면 관련 없는 조문을 나열하지 않고 한계만 짧게 안내

그래프 구조, 검색 설정과 모델은 유지하고 prompt만 바꿔 답변 길이와 시간,
Faithfulness가 어떻게 달라지는지 확인했다.

## 비교한 prompt

### 기존 Prompt v1

```text
예·적금 소비자보호 법령 안내자로서 제공된 법령 근거만 사용해
답변하세요. 근거가 부족하면 확인할 수 없다고 밝히고, 답변에는
법령명·조문번호·시행일을 명시하세요. 개별 상품의 보호 여부는
단정하지 마세요.
```

### 실험한 간결화 Prompt

```text
예·적금 소비자보호 법령 안내자입니다. 제공된 법령 근거만 사용해
다음 규칙으로 답하세요.
- 근거를 종합해 답할 수 있으면 첫 문장에 결론을 제시하고, 필요한
  조건을 설명한 뒤 결론을 직접 뒷받침하는 법령명·조문번호·시행일만
  인용하세요.
- 답할 수 없으면 '제공된 법령 근거만으로는 확인할 수 없습니다.'라고
  한 번만 쓰고, 관련 없는 조문이나 외부 지식을 덧붙이지 마세요.
- 결론 → 근거 → 필요한 한계 순서로 간결하게 쓰고 같은 내용을
  반복하지 마세요.
- 근거에 없는 금액·기관·조문을 만들거나 개별 상품의 보호 여부를
  단정하지 마세요.
```

## 고정한 조건

| 항목 | 공통 조건 |
| --- | --- |
| Graph | LangGraph `retrieve → generate` |
| Dataset | `rag-v1-dev`, 같은 Dataset version 24문항 |
| corpus | `2026-07-06` snapshot |
| 검색 | 같은 임베딩·Chroma index·상위 5개 |
| 생성 모델 | `qwen3:4b-instruct-2507-q4_K_M` |
| Judge | `gemini-3.5-flash` |
| 반복 횟수 | 각 prompt당 1회 |

기준선 revision은 `49d6ca5-dirty`, 간결화 Prompt revision은
`f6e5334-dirty`였다. 두 실행에서 24문항의 `sources`를 직접 비교한 결과 모두
같았다. 따라서 검색 결과가 아니라 생성 지시가 달라진 비교로 볼 수 있다.

다만 생성 온도와 seed를 명시적으로 고정하지 않았고 한 번씩만 실행했으므로 작은
점수 차이까지 재현된다고 단정하지 않는다.

## 전체 결과

| 지표 | Prompt v1 | 간결화 Prompt | 변화 |
| --- | ---: | ---: | ---: |
| `precision_top_5` | 0.280 | 0.280 | 동일 |
| `recall_top_5` | 0.711 | 0.711 | 동일 |
| `faithfulness` | 0.700 | 0.633 | -0.067 |
| 평균 전체 시간 | 18.35초 | 10.04초 | -45.3% |
| 중앙 전체 시간 | 17.28초 | 10.57초 | -38.8% |
| 평균 검색 Node | 1.08초 | 1.00초 | -0.08초 |
| 평균 생성 Node | 17.26초 | 9.03초 | -47.7% |
| 평균 답변 길이 | 812.9자 | 212.8자 | -73.8% |
| 전체 답변 길이 | 19,509자 | 5,107자 | -73.8% |

검색 지표는 검색 평가 대상인 15문항, Faithfulness는 해당 지표 평가 대상인
15문항의 평균이다. 나머지 9문항은 현재 기준에서 검색 및 Faithfulness 점수가
`None`이므로 위 평균에 포함되지 않는다.

이번 실행에서는 Ollama가 제공하는 실제 출력 토큰 수와 생성 시간을 보존하지 않았다.
따라서 답변 글자 수와 LangSmith 실행 시간을 사용했다. 간결화 Prompt는 검색 Node보다
생성 Node에서 8.23초가 줄었고 답변 글자 수도 크게 감소했다. 자동회귀 모델은
출력 토큰을 순서대로 생성하므로, 짧은 출력이 전체 시간을 줄인다는 해석과
일치한다.

## 답변에서 확인한 차이

### 반복은 줄었지만 필요한 내용도 함께 사라짐

A1은 정답 조문을 검색하지 못한 질문이다. Prompt v1은 관련 없는 다섯 조문을
설명한 뒤 확인할 수 없다고 반복해 622자를 생성했다. 간결화 Prompt는 25자로
줄었지만 다음과 같이 부정 표현을 잃어 반대 의미가 됐다.

```text
제공된 법령 근거만으로는 확인할 수 있습니다.
```

같은 문장은 A1, B3, D1, D2에서 나타났다. 고정 문구를 prompt에 넣어도 현재
모델이 그대로 복사한다고 보장할 수 없으며, 짧은 답변이라고 안전한 답변이 되는
것도 아니었다.

### 첫 결론이 근거 확인보다 앞선 사례

간결화 Prompt는 첫 문장에 결론을 요구했다. 일부 질문에서는 모델이 근거의 충분성을
먼저 확인하지 않고 단정적인 결론을 만들었다.

| 문항 | 간결화 Prompt 출력의 문제 |
| --- | --- |
| A2 | 이자 포함 여부를 답해야 하지만 `원금 기준`이라고 잘못 결론 |
| A5 | `외화예금은 보호되지 않습니다`라고 한 뒤 확인할 수 없다고 모순 |
| A6 | 저축은행 예금은 은행과 같은 한도로 보호되지 않는다고 잘못 결론 |
| C1 | 예금성 상품에 적용되지 않는 14일 청약철회를 예금에도 적용 |
| C3 | 검색 문맥의 시행령 제18조가 아닌 제17조를 근거로 표기 |

정답 조문을 모두 검색한 A4, A6, A8, A9, A12, B1, C1, C3에서도 잘못된 해석,
조건 누락 또는 조문 표기가 나타났다. 이 문항들은 검색 개선만으로 해결할 수 없는
생성 단계 문제다.

반대로 A4는 기존의 지나치게 조심스러운 답변에서 벗어나 적금이 법률상 `예금등`에
포함된다는 핵심을 잡았고, A10은 1,517자에서 529자로 줄면서 문장 중간에 잘리던
문제가 사라졌다. 간결화 Prompt의 모든 변화가 나빴던 것은 아니지만, 금융·법령
안내에서 허용하기 어려운 오답과 단정이 함께 늘어 전체 prompt로 채택할 수 없었다.

### 금융 상담에 맞는 말투가 되지 않음

간결화 Prompt는 답변 순서만 정했을 뿐 금융 상담 말투의 기준은 정하지 않았다. 실제
답변에는 `불법이다`, `틀렸습니다`처럼 사실관계 확인 전에 판정을 내리는 표현과
화살표 형태의 조문 표기가 나타났다. 사용자가 이해하기 쉬운 설명, 확인해야 할
조건, 다음 확인 방법은 자주 생략됐다.

따라서 `결론 → 근거 → 한계`라는 세 단어만으로는 다음 요구를 대신할 수 없었다.

- 법률 용어를 일상적인 한국어로 풀어 설명
- 사용자의 상황을 단정하지 않고 적용 조건을 구분
- 개별 상품은 설명서·공시 등 다음 확인 방법 안내
- 짧더라도 결론을 이해하는 데 필요한 이유와 주의사항 유지

## 자동 점수만으로 놓친 문제

Faithfulness 평균은 0.700에서 0.633으로 낮아졌다. 15문항 중 A4와 A9는
상승했고, A3, A6, A8, A12, C3는 하락했다.

더 중요한 한계는 점수의 평가 범위였다. 현재 Faithfulness Judge는 검색 문맥에
근거하는지만 보고 친절함, 길이, 문체와 답변의 완전성은 평가하지 않도록 되어 있다.
그래서 A1의 `확인할 수 있습니다`라는 잘못된 문장에도 1.0을 주고, 평가 이유에는
실제 출력과 반대로 `확인할 수 없다고 정확하게 밝혔다`고 기록했다.

Dataset에는 필수 주장과 금지 주장이 있지만 현재 평가 코드에서는 답변의 필수 내용
포함 여부와 금지 주장 위반을 채점하지 않는다. 이번처럼 문체와 완전성이 함께
바뀌는 prompt 비교에서는 Faithfulness만으로 채택 여부를 판단할 수 없었다.

## 확인한 속도와 품질의 관계

자연어 prompt 하나로 답변 시간까지 크게 달라진 것은 비정상적인 현상이 아니다.
prompt가 답변 길이와 작성 방식을 바꾸고, 모델은 출력 토큰을 하나씩 생성하기
때문이다. 이번에는 평균 답변 길이가 73.8% 줄면서 생성 Node 시간이 47.7%
감소했다.

다만 이 결과를 `좋은 답변은 항상 느리고, 빠른 답변은 항상 나쁘다`는 법칙으로
해석하지 않는다. 간결화 Prompt는 반복뿐 아니라 필요한 설명·조건·다음 행동까지 함께
줄였고, 현재 모델은 짧은 문장 안에서 결론과 근거를 안정적으로 압축하지 못했다.
이번에 확인한 것은 일반적인 품질·속도 한계가 아니라 **이 prompt와 이 모델 조합의
실패**다.

## 검색 개선과 다른 점

Prompt와 hybrid search·reranker는 영향을 주는 단계가 다르다.

| 변경 | 직접 바꾸는 것 | 이번 사례에서 기대할 수 있는 범위 |
| --- | --- | --- |
| Prompt·생성 모델 | 근거 해석, 답변 내용·길이·말투 | A2, A6, C1 같은 해석 오류와 상담 표현 |
| Hybrid search | 키워드 검색과 의미 검색의 후보 결합 | 정답 조문을 놓친 A1, A11, C2의 Recall |
| Reranker | 검색 후보의 순서를 다시 판단 | 상위 5개에 직접 근거를 더 앞세우는 Precision |

Hybrid search나 reranker가 정답 조문을 더 잘 전달하면 답변 품질이 나아질 가능성은
있다. 그러나 이미 정답 조문을 검색한 질문의 잘못된 해석이나 상담 말투는 고치지
못한다. 반대로 더 좋은 생성 모델도 검색 결과에 없는 조문을 근거 있게 복원할 수는
없다.

Reranking은 검색 단계의 계산 시간을 추가한다. 대신 더 정확한 근거만 남겨 모델에
전달할 문맥을 줄일 수 있다면 prompt 처리나 생성 부담이 줄 수도 있다. 이는 자동으로
보장되는 결과가 아니므로 검색 지표, 최종 답변 품질과 Node별 시간을 함께 비교해야
한다.

## 프론티어 모델 비교 전에 남은 조건

더 큰 API 모델은 근거 종합, 지시 이행, 한국어 표현과 짧은 답변 안의 정보 보존에서
나아질 가능성이 있다. 하지만 모델만 바꾸면 상담 말투와 필수 내용이 자동으로
정해지는 것은 아니며, 검색 누락도 그대로 남는다.

현재 구현은 LangChain의 system·human 메시지를 문자열 하나로 합친 뒤 Ollama에
`user` 메시지 하나로 전송한다. Ollama Chat API는 역할별 메시지 배열을 받을 수
있으므로, 모델 비교 전에는 양쪽 모델에 같은 역할과 같은 지시를 전달해야 공정하다.
또한 다음 항목을 별도로 평가해야 한다.

- 필수 주장 포함 여부
- 금지 주장과 서로 모순되는 문장
- 인용한 법령명·조문·시행일과 검색 문맥의 일치
- 금융 상담에 맞는 말투와 다음 확인 방법
- 답변 길이, 실제 출력 토큰, 첫 토큰·전체 시간과 API 비용

Structured Output은 정해진 필드가 있는 응답 형태를 안정시키는 수단이다. JSON
schema를 지켰다는 사실이 각 필드의 법률 내용까지 옳다는 뜻은 아니므로 위 품질
평가를 대신하지 않는다.

## 결정

간결화 Prompt 후보는 채택하지 않는다.

반복과 전체 응답 시간은 줄였지만, 다음 이유로 금융 소비자보호 안내에 사용할 수
있는 개선으로 보지 않았다.

1. 근거 부족 안내의 부정 표현이 뒤집혀 반대 의미가 됐다.
2. 짧은 첫 결론이 잘못된 법률 해석과 단정을 강화했다.
3. 필요한 조건·주의사항·다음 확인 방법이 자주 빠졌다.
4. Faithfulness도 낮아졌고 현재 자동 평가가 중요한 실패를 놓쳤다.
5. 금융 상담에 필요한 말투와 설명 수준을 충족하지 못했다.

기존 Prompt v1도 반복, 장문과 근거 밖 생성 문제가 있으므로 최종안은 아니다.
이번 실험에서는 v1을 비교 기준선으로 유지하고, 간결화 Prompt의 속도 수치만 떼어
성공으로 보지 않는다.
