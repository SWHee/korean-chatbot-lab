# 근거 부족 스트림 조기 전환

- 작성일: 2026-08-01
- 상태: 구현·단위 검증 완료, UI 시간 비교 전
- 대상: `can_answer=false`인 법령 RAG 스트리밍 응답

## 관찰

정상 답변은 생성 중인 본문이 계속 표시되지만, 근거 부족 안내는 구조화 JSON이 모두
완성된 뒤 한꺼번에 보였다. LangSmith에는 `streaming=true`가 기록됐지만 이는
스트리밍 endpoint를 실행했다는 입력값이며, 사용자에게 첫 문장이 언제 보였는지를
의미하지 않는다.

구조화 스트림의 `result`는 다음 순서다.

```text
[can_answer, source_ids, answer]
```

기존 코드는 세 값이 모두 도착해야 처리했다. 따라서 첫 값으로 `false`를 이미 받아도
빈 `source_ids`와 `answer`가 완성될 때까지 기다린 뒤 고정 안내를 반환했다.

## 선택

| 선택지 | 판단 |
| --- | --- |
| 고정 안내를 `sleep`으로 천천히 전송 | 보이는 효과를 위해 응답 시간을 인위적으로 늘리므로 제외 |
| 근거 부족 문장도 모델이 생성 | 말투 편차와 근거 밖 문장 위험이 다시 생기므로 제외 |
| 검색 유사도만으로 모델 호출 생략 | 답변 가능 여부를 잘못 판단할 수 있어 별도 검색 실험 필요 |
| 스트림의 첫 `false`에서 고정 안내로 전환 | 추가 모델 호출 없이 안전성과 조기 응답을 함께 유지 |

`false`는 답변을 제한하는 보수적인 판단이다. 부분 JSON에서 이 값이 확인된 뒤 나머지
모델 출력을 사용자에게 보여주지 않아도 기존 안전 경계는 약해지지 않는다. 따라서
마지막 방법을 선택했다.

## 적용

`stream_answer_question()`이 부분 `result`의 첫 값을 먼저 확인하도록 변경했다.

```text
부분 JSON에서 false 확인
  → 남은 구조화 모델 스트림 종료
  → 코드가 관리하는 고정 안내를 즉시 yield
  → 함수 종료
```

정상 답변은 기존처럼 `source_ids`와 답변 본문을 검증하면서 스트리밍한다. 고정 안내는
줄 단위로 즉시 전달하며 시각 효과를 위한 지연은 추가하지 않았다. 네트워크가 조각을
합칠 수 있으므로 항상 타이핑 효과처럼 보인다고 보장하지는 않지만, 완성된 구조화
응답을 기다리던 불필요한 대기는 제거했다.

## 결과

단위 테스트에서 `[False]` 하나만 반환한 뒤 더 진행하면 실패하도록 생성기를 구성했다.
현재 구현은 그 실패 지점까지 진행하지 않고 모델 스트림을 닫은 뒤, 동일한 고정 안내를
여러 조각으로 반환한다.

확인된 결과는 다음과 같다.

- `false` 이후의 구조화 응답을 기다리지 않음
- 남은 모델 스트림 종료
- 기존 근거 부족 고정 안내와 안전 정책 유지
- 정상 답변 스트리밍 경로 유지

아직 UI에서 첫 안내가 보이기까지의 시간과 전체 시간을 전후 비교하지 않았다. 공급자
요금도 중간 취소 시점의 과금 정책에 따라 달라질 수 있으므로 비용 감소로 기록하지
않는다.

## 비교·결정

인위적인 지연이나 추가 분류 호출 없이 불필요한 대기를 제거하므로 현재 구현을
채택한다. UI 수동 확인에서는 근거 부족 질문으로 첫 안내 시간과 LangGraph generate
Node 시간을 확인한다. 이후 수치가 생기면 이 문서의 결과에 이전·이후 값을 추가한다.
