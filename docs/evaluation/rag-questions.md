# RAG 평가 질문

- 작성일: 2026-07-06
- 상태: 질문·조문 원문 대조, Dataset v1 dev 변환 완료
- 용도: RAG 베이스라인 측정과 이후 LangSmith 평가의 기준 질문 세트

기계 판독용 데이터는 [`data/evaluation/rag-v1-dev.jsonl`](../../data/evaluation/rag-v1-dev.jsonl)에
있다. 이 문서는 질문을 사람이 읽고 검토하기 위한 설명이고, 실제 평가 코드는 JSONL을
사용한다.

## A1·B2 같은 ID의 의미

알파벳은 질문 유형, 숫자는 그 유형 안에서의 순번이다. 모델이나 평가 지표가 만든
특별한 용어가 아니라 질문을 계속 같은 이름으로 추적하기 위한 ID다.

| 접두사 | 질문 유형 | 확인하려는 동작 |
| --- | --- | --- |
| A | 법령 근거형 | 정확한 법령·조문을 찾아 근거로 답하는지 |
| B | 개정시점·시행일형 | 현행 조문과 과거 적용관계를 구분하는지 |
| C | 잘못된 전제형 | 질문에 동의하지 않고 틀린 전제를 교정하는지 |
| D | 범위 밖 상품형 | 최신 상품 정보가 없을 때 단정하지 않는지 |
| E | 일반 개념 대조군 | 현재의 법령 근거 제한을 지키는지 |

따라서 A5는 A 유형의 다섯 번째 질문, B2는 B 유형의 두 번째 질문이다. ID를 유지하면
LangSmith에서 실험이 바뀌어도 같은 질문의 검색 순위와 답변 점수를 비교할 수 있다.

## 구성과 평가 기준

다섯 유형(A~E)으로 구성한다. 질문별 세부 rubric은 JSONL의 `required_claims`,
`forbidden_claims`, `expected_behavior`에 기록한다.

- 법령 근거형(A)·시행일형(B): 법령명과 조문을 인용하는지, 시행일이
  관련되면 명시하는지
- 잘못된 전제형(C): 질문의 틀린 전제를 교정하는지
- 범위 밖 상품 탐색형(D): corpus로 답할 수 없음을 고지하고 공식 확인처를
  안내하는지, 억지로 생성하지 않는지
- 일반 개념 대조군(E): 현재의 "법령 근거만 사용" 규칙을 지키며 범위 한계를
  안내하는지

기대 근거의 조문 번호는 2026-07-06 법령 원문 대조로 확정했다. A5·B2·B3는
현행 조문 인덱스만으로 직접 답하기 어려워 retrieval 평가에서 제외한다. D·E도
검색 정답보다 범위 안내가 중요한 질문이라 같은 검색 지표를 적용하지 않는다.

## 네 가지 RAG 지표와 Dataset

| 지표 | 비교 대상 | Dataset이 제공하는 값 | 적용 범위 |
| --- | --- | --- | --- |
| Context Precision | 질문 ↔ 검색된 조문의 순위 | primary·supporting gold 조문 | retrieval 가능 15개 |
| Context Recall | reference의 핵심 주장 ↔ 검색 문맥 | primary gold·`required_claims` | retrieval 가능 15개 |
| Faithfulness | 생성 답변 ↔ 실제 검색 문맥 | 생성 답변과 평가 target이 보존한 조문 본문 | retrieval 가능 15개 |
| Answer Relevancy | 질문 ↔ 생성 답변 | `question`·생성 답변 | 전체 24개 |

Context Precision과 Recall은 비슷해 보여도 보는 실패가 다르다. Precision은 불필요한
조문이 정답보다 앞에 오는지 보고, Recall은 답변에 필요한 근거를 빠뜨렸는지 본다.
Faithfulness는 검색이 잘됐는지와 별개로 모델이 근거 밖 주장을 만들었는지 확인한다.
Answer Relevancy는 답변이 질문을 직접 다뤘는지 보며, 사실이 맞는지는 이 점수만으로
판정하지 않는다.

현재 Dataset은 이 지표들을 계산할 입력을 갖추었지만 아직 점수를 실행한 상태는
아니다. 다음 단계에서 실제 `/ask-rag`와 같은 검색·생성 경로의 출력과 연결한다.
현재 API의 `sources`에는 조문 본문이 없으므로, 평가 target은 검색된 본문을
`retrieved_contexts`로 별도 보존해야 한다.

## A. 법령 근거형 (주력, 12개)

| # | 질문 | 기대 근거 |

| A1 | 은행이 파산하면 내 예금은 얼마까지 보호받나요? | 예보법 §32, 시행령 §18 — 1억원, 2025-09-01 시행 |
| A2 | 보호 한도 1억원은 원금 기준인가요, 이자 포함인가요? | 예보법 §32, §2(예금등채권 정의) — 원금+소정이자 합산 |
| A3 | 여러 은행에 예금을 나눠 두면 각각 보호받나요? | 예보법 §32(1인당 기준), 시행령 §18 — 금융회사별 적용 설명 |
| A4 | 적금도 예금자보호 대상인가요? | 예보법 §2 부보예금 정의 |
| A5 | 외화예금도 보호되나요? | 현행 조문 문면에 '외화' 명시 없음 — 예금등 정의(예보법 §2) 해석 설명 + 공식 확인 안내 기대 |
| A6 | 저축은행 예금도 은행과 같은 한도로 보호되나요? | 예보법 §2·§32, 시행령 §18 |
| A7 | 은행이 예금 상품을 팔 때 무엇을 설명할 의무가 있나요? | 금소법 §19, 시행령 §13(타 법률에 따른 보호 여부 포함) |
| A8 | 금소법에서 예금은 어떤 상품 유형으로 분류되나요? | 금소법 §3 — 예금성 상품 |
| A9 | 은행이 대출을 조건으로 적금 가입을 강요하면 불법인가요? | 금소법 §20 불공정영업행위 금지 |
| A10 | 금융상품 광고에는 어떤 규제가 있나요? | 금소법 §22, 시행령 §18~§20 |
| A11 | 설명을 제대로 못 받고 가입했다면 어떤 권리가 있나요? | 금소법 §47 위법계약해지권, §44 손해배상 |
| A12 | 예금보험료는 예금자가 내는 건가요? | 예보법 §30 — 부보금융회사 납부 |

주의: A4~A6은 상품 유형의 일반 원칙 설명과 함께 "개별 상품의 보호 여부는
공시·상품설명서 확인 필요" 안내를 포함해야 정답으로 본다. A11은 권리가
자동 성립하지 않으므로 적용 조건(법 위반 존재, 행사기간 등) 언급 여부도
본다.

## E. 일반 개념 대조군 (2개)

일반 모델 지식으로는 답할 수 있지만 현재 RAG prompt는 제공된 법령 근거만 사용하도록
제한한다. 따라서 현재 기준선에서는 아는 척해 답하지 않고 corpus 범위를 안내하는지
확인한다. 이후 LangGraph에 일반 질문 경로가 생기면 이 유형의 기대 동작을 새 Dataset
버전에서 바꾼다.
