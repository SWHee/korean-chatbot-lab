# Streamlit 채팅 UI 구현 회고

- 작성일: 2026-07-17

## 왜 지금 만들었나

Swagger와 `curl`만으로도 API 동작은 확인할 수 있지만, 답변이 길어질수록 실제 사용자가
어떻게 읽는지 체감하기 어려웠습니다. 현재 법령 RAG를 바꾸지 않고도 질문과 스트리밍
답변을 한 화면에서 확인할 수 있도록 Streamlit UI를 추가했습니다.

## 이번에 구현한 범위

- `/ask-rag/stream`을 호출하는 법령 RAG 채팅 화면
- 답변이 생성되는 대로 표시하는 텍스트 스트리밍
- 브라우저 안에서 유지되는 대화 기록과 대화 초기화
- 처음 사용해 볼 수 있는 예시 질문 3개
- FastAPI 주소 설정과 현재 답변 범위 안내

UI는 금융 서비스에 필요한 신뢰감과 읽기 편한 인상을 우선했습니다. 푸른 대화 배경과
노란 사용자 말풍선을 사용하고, 사용자와 챗봇의 메시지를 좌우로 나눠 대화 흐름을 바로
알아볼 수 있게 구성했습니다. 짧은 서비스 설명과 주의 문구도 답변보다 먼저 배치했습니다.

## 구현하며 확인한 점

Streamlit의 `st.chat_message`는 사용자와 챗봇 메시지를 구분하고,
`st.write_stream`은 FastAPI가 보내는 텍스트 조각을 도착하는 순서대로 표시합니다.
따라서 backend의 생성 코드를 UI에 다시 작성하지 않고 HTTP API만 연결할 수 있었습니다.

화면에 이전 대화가 남는 것과 모델이 대화 문맥을 기억하는 것은 다릅니다. 지금은
Streamlit의 session state가 메시지를 화면에 보관하지만, FastAPI에는 새 질문 하나만
전달합니다. 멀티턴 문맥 관리는 이후 상태 관리가 실제로 필요할 때 별도로 다뤄야 합니다.

## 현재 한계

- 금융상품 한눈에 API가 아직 연결되지 않아 상품을 추천하거나 비교하지 않습니다.
- 스트리밍 endpoint는 답변 본문만 보내므로 검색 출처를 별도 카드로 표시하지 않습니다.
- Streamlit보다 먼저 FastAPI와 Ollama를 실행해야 합니다.

이번 UI의 목적은 완성된 금융 서비스를 만드는 것이 아니라, 현재 RAG 답변을 사용자
관점에서 빠르게 읽고 디버깅할 수 있는 최소 화면을 마련하는 것입니다.
