# RAG 주제와 데이터를 고른 과정

- 작성일: 2026-07-06
- 현재 상태: 법령 원문 수집·인덱싱 완료

## 해결하려던 문제

RAG를 구현하려면 먼저 답변할 주제와 근거 문서를 정해야 했다. 이 프로젝트에는
다음 조건이 중요했다.

- 신입 개발자가 도메인과 구현 이유를 직접 설명할 수 있을 것
- 원문을 저장소에 포함해 인덱싱을 재현할 수 있을 것
- 문서 구조가 있어 파싱과 청킹을 학습할 수 있을 것
- 질문과 정답 근거를 만들어 검색을 평가할 수 있을 것

금융 중에서도 사업보고서나 자본시장처럼 전문 지식이 많이 필요한 영역 대신,
예·적금 이용자가 접하는 보호 제도와 소비자 권리로 범위를 좁혔다.

## 선택한 주제와 corpus

주제는 **예·적금 이용자를 위한 소비자보호 법령 Q&A**다. corpus는 다음 네
문서다.

1. 금융소비자 보호에 관한 법률
2. 금융소비자 보호에 관한 법률 시행령
3. 예금자보호법
4. 예금자보호법 시행령

법령은 저작권법 제7조에 따라 원문을 저장소에 포함할 수 있고,
국가법령정보 공동활용 API가 구조화된 XML을 제공한다. 조·항·호와 시행일이
표시되어 있어 조문 단위 파싱과 출처 메타데이터 구성에도 적합했다.

시행령까지 포함한 이유는 핵심 정보가 법률에만 있지 않기 때문이다. 예금자보호
한도 1억원은 예금자보호법 시행령 제18조에 있고, 금융상품 설명사항의 구체적인
내용도 금융소비자보호법 시행령에 있다.

## 실제 구현

- [`collect_laws.py`](../../../scripts/collect_laws.py): 현행 법령 검색과 XML 수집
- [`data/laws/`](../../../data/laws): 2026-07-06 기준 원문 snapshot
- [`statutes.py`](../../../src/chatbot/statutes.py): XML을 조문 단위 `Article`로 변환
- [`rag-questions.md`](../../evaluation/rag-questions.md): 평가 질문 24개

정기 동기화는 구현하지 않았다. 현재 목표는 작은 고정 corpus로 RAG의 각 단계를
학습하고 재현하는 것이다. 답변에는 snapshot의 시행일을 근거로 사용하고, 최신
법률 상담 서비스처럼 표현하지 않는다.

## 서비스 역할 구분

법령 RAG가 모든 금융 질문을 해결하지는 않는다.

| 질문 | 담당 영역 |
| --- | --- |
| 보호 한도·설명의무·소비자 권리 | 법령 RAG |
| 최신 예·적금 상품 후보 | 이후 Finlife 공시 API |
| 개별 상품의 실제 보호 여부 | 상품 공시·상품설명서 확인 |
| 예금과 적금 같은 일반 개념 | 생성 모델의 기본 지식 |

따라서 현재 법령 corpus로 최신 금리나 특정 상품을 억지로 답하지 않는 것도 평가
대상이다. 혼합 질문과 상태 관리가 실제로 필요해질 때 LangGraph를 검토한다.

## 배운 점

- RAG 데이터는 구할 수 있는지만이 아니라 저장·가공·재배포 조건도 확인해야
  한다.
- 주제 범위를 먼저 정하면 필요한 문서와 범위 밖 질문이 함께 선명해진다.
- 법률과 시행령을 함께 봐야 실제 사용자 질문의 근거가 완성되는 경우가 있다.
- 정적인 법령 검색과 변동하는 상품 조회는 같은 데이터 처리 문제가 아니다.
