# 임베딩 모델 선정 — 내 질문으로 비교하기

- 작성일: 2026-07-06
- 현재 상태: KURE-v1 선정·전체 인덱싱 완료

## 해결하려던 문제

322개 법령 청크를 벡터로 바꾸고 한국어 질문과 가까운 조문을 검색할 모델이
필요했다. 무료 오픈소스, 상업 이용 가능한 라이선스, M2 Pro 16GB 로컬 실행,
한국어 검색 품질을 기준으로 비슷한 규모의 모델 네 개를 비교했다.

| 모델 | 특징 |
| --- | --- |
| multilingual-e5-large | 다국어 기준선, 512 token 입력 |
| bge-m3 | 다국어 모델, KURE-v1의 기반 모델 |
| KURE-v1 | bge-m3를 한국어 검색에 맞게 추가 학습 |
| Qwen3-Embedding-0.6B | 비교 당시 최신 세대 후보 |

## 평가 방법

평가 질문 중 corpus에서 정답 조문을 직접 확인할 수 있는 15개를 사용했다.
A5·B2·B3은 외화, 경과규정, 종전 한도 정보가 현재 조문 snapshot에 직접 없어
retrieval 평가에서 제외했다.

긴 조문의 여러 자식 청크가 순위를 반복해서 차지하지 않도록 법령명과 조문번호가
같은 청크 중 최고 점수만 사용했다.

- Hit@k: 정답 조문 중 하나라도 상위 k개에 있는 비율
- Recall@k: 필요한 정답 조문 중 상위 k개에서 찾은 비율
- MRR: 첫 정답 조문 순위의 역수 평균

모델별 prefix와 query prompt 규칙을 적용하고 모든 벡터를 정규화했다. 전체
재현 코드는 [`compare_embeddings.py`](../../../scripts/compare_embeddings.py)에
있다.

이 결과는 세션⑤ 당시의 초기 정답 조문을 사용한다. 이후 만든 Dataset v1은 A2·A6·C2의
필수 조문을 확장했으므로, Dataset v1으로 계산한 수치와 직접 비교하지 않는다.

## 결과

| 모델 | Hit@1 | Hit@5 | Recall@5 | MRR | 인덱싱 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| multilingual-e5-large | 0.333 | 0.533 | 0.500 | 0.448 | 26초 |
| bge-m3 | 0.267 | 0.800 | 0.667 | 0.497 | 20초 |
| **KURE-v1** | **0.400** | **0.800** | **0.700** | **0.559** | 20초 |
| Qwen3-Embedding-0.6B | 0.333 | 0.533 | 0.467 | 0.444 | 84초 |

KURE-v1은 15문항 중 12개에서 정답 조문을 top-5에 올렸고 전체 지표가 가장
좋았다. e5-large는 청크 54개가 512 token 입력 한도를 넘어 현재 청킹과 맞지
않았다. 최신 모델이라는 이유만으로 추가한 Qwen3 후보도 이 corpus에서는 가장
좋지 않았다.

모든 모델이 C2의 잘못된 전제 질문에서 낮은 성능을 보였다. “정부가 세금으로
전액 보상한다”는 구어체 표현과 법령 문구가 멀기 때문이다. 이 문제는 모델을
바꾸는 것보다 이후 질의 변환이나 답변 단계에서 다룰 후보로 남겼다.

## 현재 구현과 한계

[`embedding.py`](../../../src/chatbot/embedding.py)는 `nlpai-lab/KURE-v1`을
불러와 batch size 16, 정규화 옵션으로 1024차원 벡터를 만든다. 인덱싱과
질의가 같은 모델·전처리를 사용해야 기존 Chroma 벡터와 비교할 수 있다.

평가 질문이 15개뿐이므로 이 결과는 일반적인 한국어 임베딩 순위가 아니라 이
프로젝트 안에서 후보를 선택한 근거다. 최종 답변 품질은 RAG 체인이 완성된 뒤
별도로 평가한다.
